# U-MoE-Fusion 关键结构与训练机制图解

本节集中展示 U-MoE-Fusion 的总体框架、统一预处理、窗口注意力、任务条件 MoE-FFN，以及与模型特征相匹配的分布式训练机制。五幅图从数据进入网络开始，逐层展开核心计算模块，最后说明训练并行策略的选择依据。

## 1　U-MoE-Fusion 总体框架

![U-MoE-Fusion 统一多模态图像融合总体框架](../Materials/figs/fig_u_moe_fusion_framework.png)

> **图注｜U-MoE-Fusion 统一多模态图像融合总体框架。** 三类异构源图像经统一亮度预处理后进入一套共享的三分支多尺度主干；各 Transformer 块以 8×8 窗口注意力提取局部上下文，并通过任务条件 MoE-FFN 实现共享知识与任务特异知识的协同建模。三路特征汇聚后由像素级决策图完成双源亮度融合，彩色任务再利用源色度重建 RGB 输出。

图的 A 区说明“一套权重、三类任务”的输入方式。红外–可见光、PET/SPECT–MRI 和 GFP–相位衬度三类源对虽然具有不同的色彩空间、分辨率与成像机理，但都先转换到统一的 Y 亮度域。两路亮度 `Y_A`、`Y_B` 归一化并拼接成双通道输入，同时携带任务标识 `t`；训练阶段使用不缩放的 170×170 同坐标裁块，并通过任务配额平衡避免样本量较大的任务主导优化。源图像的 Cb/Cr 不进入主干，只在彩色结果重建时使用。

图的 B 区是共享的多尺度 U-MoE 主干。3×3 卷积 stem 首先将输入映射到统一特征空间，随后特征分别进入浅层、中层和深层三条分支。每条分支由不同深度的自适应卷积模块（ACM）与四个 Transformer 块组成：窗口注意力负责在非重叠局部窗口内建立空间依赖，任务条件 MoE-FFN 则以一个常开共享专家保留跨任务公共知识，并从 12 个路由专家中为每个 token 稀疏选择 top-2 专家。三条分支的输出经过末端 ACM 后逐元素相加，使局部纹理、区域结构和深层语义在同一特征表示中汇聚。

图的 C 区给出融合和训练目标。汇聚特征经 1×1 卷积与 sigmoid 生成像素级决策图 `w`，最终亮度按 `F_Y=w·Y_A+(1-w)·Y_B` 进行凸组合；因此每个位置都能根据两路源图的有效信息自适应确定贡献比例。红外–可见光任务直接输出融合亮度，医学和显微任务则将融合亮度与保留的源 Cb/Cr 重组为 RGB。训练时，maxfuse 目标联合约束最大响应、结构相似性、联合梯度与内容信息，MoE 另使用权重为 0.01 的负载均衡辅助损失。底部的 grouped-capacity 调度、fused SDPA、`torch.compile` 和 DDP overlap 属于执行优化，不改变上方网络的推理语义。

## 2　统一多任务亮度预处理

![U-MoE-Fusion 统一多任务亮度预处理](../Materials/figs/fig_u_moe_unified_preprocessing_detail.png)

> **图注｜U-MoE-Fusion 的统一多任务亮度预处理流程。** 三类有序源对经文件配对、BT.601 亮度提取、尺寸对齐和 `[0,1]` 归一化后，被统一组织为双通道 Y 域输入；训练路径采用反射填充、同坐标 170×170 裁块和任务平衡采样，推理路径保留完整分辨率。源 Cb/Cr 仅通过推理旁路参与最终颜色重建。

图的左侧首先固定三类任务的源顺序与任务编号：IR–VIS、Medical 和 Microscopy 分别对应 `task_id=0、1、2`，其中 Source A 为彩色或伪彩源，Source B 为灰度结构源。数据加载器通过相同文件名或共同 stem 建立一一对应的有序图像对，避免两路源在后续处理中交换语义。彩色源按 BT.601 关系提取 `Y=0.299R+0.587G+0.114B`，灰度源直接作为 Y；两路亮度均除以 255，从而把原始模态差异收敛为统一的数值接口。

进入采样阶段前，系统以 Source A 的空间尺寸为基准检查两路图像形状，仅在尺寸不一致时对 Source B 做双线性对齐。训练路径先对小于 170 的边执行反射填充，再使用完全相同的 `(top,left)` 坐标从 A、B 裁取 170×170 区域，不进行额外缩放；随后按每个任务约 4000 个裁块建立固定种子的平衡索引。推理路径不裁块，以批大小 1 保留对齐后的完整 `H×W` 分辨率。两条路径最终都形成 `X=concat(Y_A,Y_B)`，其训练形状为 `2×170×170`，推理形状为 `2×H×W`，并与 `task_id` 一同送入共享网络。

图底部的色度支路与亮度主路径相互独立。彩色源的 Cb/Cr 在推理期间被缓存，灰度源则以 128 表示中性色度；需要生成彩色结果时，系统依据色度相对 128 的偏离幅度融合两路 Cb/Cr，再与网络预测的融合 Y 进行 YCbCr–RGB 逆变换。这样既可让主干只学习跨任务一致的结构和亮度融合规律，又能在医学伪彩与 GFP 荧光任务中保留具有解释意义的颜色信息。

## 3　8×8 窗口注意力

![U-MoE-Fusion 8×8 窗口注意力详细结构](../Materials/figs/fig_u_moe_window_attention_detail.png)

> **图注｜U-MoE-Fusion 中 8×8 窗口注意力的详细结构。** 输入特征经 LayerNorm 和反射填充后被划分为非移位 8×8 窗口，每窗 64 个 token 通过八头 Q/K/V 投影和带二维相对位置偏置的 fused SDPA 建模局部空间关系；多头输出经拼接、线性投影、窗口还原和裁剪后，与原始特征进行残差相加。

输入特征先由 `(B,C,H,W)` 重排为通道后置形式并执行 LayerNorm。最终模型的通道数为 `C=96`，窗口大小为 8；当 H 或 W 不能被 8 整除时，只在右侧和下侧进行反射填充。以 170×170 训练裁块为例，特征会被填充到 176×176，并划分为 `22×22=484` 个互不重叠的窗口，每个窗口展平为 64 个 token。该实现采用普通非移位窗口，不包含循环移位，也不需要跨窗 attention mask。

每个窗口通过共享线性层将 96 维特征投影为 288 维，再拆分为 Q、K、V，并重排为 8 个注意力头；因此每个头的维度为 12，张量形状为 `64×12`。8×8 网格在两个方向上的相对位移都覆盖 `[-7,7]`，由此形成 `15×15=225` 个可学习相对位置偏置索引，并映射为每个头的 `64×64` 加性偏置矩阵。单头计算遵循 `A_h=softmax(Q_hK_h^T/√12+B_rel)` 与 `O_h=A_hV_h`，实现中使用 fused scaled dot-product attention，将缩放、偏置、softmax、dropout 和加权求和合并到高效内核。

八个头的输出随后拼接回每个 token 的 96 维表示，并经过 `Linear(96→96)` 投影。窗口内的 64 个 token 被重新排列成 8×8 网格，所有窗口再通过 window reverse 恢复为完整特征图；若前面进行了填充，则裁回原始 `H×W`。最后，注意力结果与进入该模块前的 shortcut 相加，得到 `F_attn=F+WindowAttention(LayerNorm(F))`，再送入后续 LayerNorm 和任务条件 MoE-FFN。

## 4　任务条件 MoE-FFN

![U-MoE-Fusion 任务条件 MoE-FFN 详细结构](../Materials/figs/fig_u_moe_ffn_detail.png)

> **图注｜U-MoE-Fusion 中任务条件 MoE-FFN 的详细结构。** 归一化 token 与任务嵌入共同生成 softmax 路由概率，一个共享专家对全部 token 常开，12 个路由专家中仅 top-2 被稀疏激活并按归一化权重汇聚；路由输出与共享专家输出相加后再通过残差连接返回 Transformer 主路径，右侧给出单个 `C→4C→C` FFN 专家的内部结构。

窗口注意力输出首先经第二个 LayerNorm，并展平为 `T=B×H×W` 个 C 维 token。任务编号 `t` 经嵌入层得到 `e_t`，再与 token 特征相加形成路由条件 `z=h+e_t`；线性门控与 softmax 为 12 个路由专家产生概率分布，从中选择概率最大的两个专家，并对选中权重重新归一化。图中高亮的 E3、E9 仅表示某一次 token 路由示例，实际专家选择会随 token、样本和任务动态变化。

专家计算由共享路径和稀疏路由路径组成。共享专家 `E_s` 对每个 token 始终执行，以维持三类任务之间稳定的公共表示；路由路径仅计算 top-2 专家，并按权重 `α_i` 汇聚。两条路径最终形成 `F_MoE=E_s(h)+Σα_iE_i(h)`。每个专家都采用相同但参数独立的两层前馈结构，即 `Linear(C→4C)→GELU→Dropout→Linear(4C→C)→Dropout`。MoE 输出再与进入模块前的 `F'` 相加得到 `F''`，从而保留 Transformer 块的残差传播路径。

黄色 grouped-capacity 模块表示实际的批量调度方式：token 按目标专家分组，每个专家容量设为 `max(1,floor(1.25Tk/E))`，其中 `k=2、E=12`，再通过规则化张量上的批量 GEMM 完成专家计算。该调度只优化执行效率，不改变 top-2 路由语义。训练阶段还计算 `L_balance=12Σ(f_i·p_i)`，以 0.01 的权重加入总损失，约束专家接收比例与平均路由概率，降低少数专家长期过载或其余专家失活的风险；图中的红色虚线因此不属于推理数据流。

## 5　分布式训练机制比较

![分布式训练机制及其与 U-MoE-Fusion 的匹配关系](../Materials/figs/distributed_parallelism_comparison.png)

> **图注｜分布式训练机制的切分对象、通信模式及其与 U-MoE-Fusion 的匹配关系。** 图中以统一的四卡示意比较 DDP、梯度归约重叠、分布式优化器、ZeRO/FSDP、成本感知数据分片、TP、PP、EP、Ulysses Parallelism 和 Context Parallelism，并分别标出其切分对象、主要通信操作以及对当前轻量级、激活主导模型的适用性。

图中的十个模块回答三个问题：系统切分的是数据、模型状态、张量、层、专家还是序列；主要使用 All-Reduce、Reduce-Scatter/All-Gather、All-to-All、P2P 还是 Ring P2P；该通信成本是否对应 U-MoE-Fusion 的真实瓶颈。DDP 在每张 GPU 上保留完整模型，并把不同 mini-batch 分给不同 rank，反向阶段通过 All-Reduce 同步梯度。梯度归约重叠并不是新的切分维度，而是在梯度桶就绪后立即异步发起通信，使其与剩余反向计算并行；当前 PyTorch DDP reducer 已具备该能力。

分布式优化器和 ZeRO/FSDP 主要针对参数、梯度及优化器状态过大的模型，前者通过 Reduce-Scatter 切分梯度和优化器状态并按需 All-Gather 参数，后者还可进一步切分参数。TP 将单层大矩阵切到多卡并在层内频繁通信，PP 将连续网络层分成多个 stage 并用 micro-batch 填充流水线。它们分别适合大状态、大宽度或大深度网络，而 U-MoE-Fusion 仅约 4.11 M 参数、主干宽度 `C=96` 且层数较少，因此这些机制能够节省的本地状态有限，却会增加高频 collective 或流水线空泡。

EP 按 GPU 放置不同专家，需要两次 All-to-All 完成 token 分发与结果回收；当前 12 个小专家可以在单卡内通过 grouped-capacity 批量计算，跨卡交换 token 反而可能取代高效的本地 GEMM。Ulysses Parallelism 通过两次 All-to-All 在序列切分与注意力头切分之间转换，Context Parallelism 则让 K/V 块沿环形 P2P 在 rank 间轮转，两者都面向超长序列注意力。本文每个窗口仅有 64 个 token、总头数为 8，不存在需要跨 GPU 拆分的长上下文。成本感知数据分片只有在样本耗时确实异构时才有意义；固定形状输入若只按任务标签重新分配，并不能自动改善负载均衡。

当前模型的 FP32 参数、梯度和 Adam 状态合计不足 0.1 GB，而实测训练峰值显存约为 61–76 GB，主要开销来自激活、融合损失分支和 MoE 容量缓冲。因此图中给出的最终选择是 **DDP + 异步分桶重叠 + gradient bucket view + static graph + 约 8 MiB 两桶 + fused Adam**：它直接扩展数据吞吐并隐藏一部分梯度通信，又不会为当前并不存在的模型状态、超宽层、跨卡专家或长上下文瓶颈引入额外通信。
